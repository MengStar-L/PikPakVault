# 使用与恢复说明

安装、备份迁移与更新请参阅 [README](../README.md)。

## 使用流程

1. 添加并验证账号，程序默认使用 `My Pack/PikPakVault` 专用文件夹。只有当前账号会接收新的保存任务。
2. 点击“添加资源”，输入一个或多个链接；分享可输入提取码并预览、选择顶层文件或文件夹。任务会递归保存完整来源路径。
3. 通过文件界面整理目录。本地路径是期望状态，远端重命名、移动或删除只影响可用性状态。
4. 在恢复中心检查远端，选择单文件、文件夹或全部缺失，核对目标账号和容量后手动开始。
5. 需要切号时，先验证备用账号再切换；旧账号任务保留为暂停。恢复中心会显示新账号尚未拥有的资源，确认后按本地目录重建。

在“设置 → 云端保存位置”可以自定义从 PikPak「全部文件」开始的路径，例如 `My Pack/资料/收藏`。保存后，当前账号的专用根目录会移动并改名，保持远端目录 ID 和本地资源映射；其他账号在切换时应用。旧版 `PikPakVault-<实例短ID>` 会在升级启动后安排迁移。父目录不存在时逐层创建，同名目标不会自动合并；目录被删除时仍需手动恢复，迁移状态和失败原因可在设置及传输任务中查看。

主动删除进入本地回收站，同时安排当前账号中的对象进入 PikPak 回收站。普通恢复跳过主动删除条目；“永久移除备份记录”只删除本地记录，并要求相关任务已完成或取消，不清空共享账号的远端回收站。

来源失效时在文件详情中替换来源；建议保持相同的来源内部结构。路径不能对应时会用大小与已保存哈希寻找唯一匹配，无法唯一识别则报告问题。

普通磁链和分享直接提交到目标目录，以返回的任务 / 文件 ID 登记结果，不再为每个导入创建暂存目录。部分分享接口可能忽略目标目录；程序只把明确属于本次转存的结果移到最终位置一次。返回原有文件或分享发布者 ID 时暂停；缺少可确认的结果 ID 时，可在任务详情中手动关联。写响应丢失后先核对新任务、来源和目标目录，不会盲目重复提交。同名不同内容不覆盖。

PikPak 任务卡在 99% 或仍显示进行中时，程序会读取实际文件树，完整读取分页，检查所有文件完成状态、可用的目录总大小及来源清单。两次完整结果相同且至少相隔 30 秒后，可按文件核验结果完成本地登记，不必等待上游任务状态刷新。空目录、未完成文件、分页失败和变化中的目录不会被误判完成。若磁链未提供完整清单或目录总大小，核验只能依据上游当前可见的完整文件和稳定目录，不能证明上游尚未暴露的文件数量。

每账号请求至少间隔 0.5 秒，写操作至少间隔 2 秒；任务查询间隔为 15 / 30 / 60 / 120 秒，最多每 2 分钟一次。遇到 429 时整个账号冷却至少 60 秒，并遵守更长的 Retry-After；需要验证时暂停该账号后续任务。降低请求频率不能保证上游不触发验证。

哈希命中直接使用最终目录和名称。来源批次恢复仍可能需要隔离，在专用根目录下的 `恢复暂存` 内按批次保留结果，避免重建时覆盖同名对象。已有 `.vault-task-` / `.vault-instant-` 检查点继续沿用，不因升级重复转存或搬动暂存目录。程序每 30 分钟从本地记录安排一次空目录整理，只检查已完成任务记录的暂存 ID；原位置和名称未变、完整分页确认空且没有资源/未完成任务引用时，批量移入 PikPak 回收站。非空、改名、移位、取消或暂停任务仍引用的目录会保留，结果可在传输任务中查看。

## 实机验收清单

在真实账号投入使用前，用两个测试账号和可删除的测试文件验收：

- 密码登录、令牌导入、自动续期、验证挑战及失败提示。
- 磁链、嵌套及带提取码分享、多页分享列表、返回结果 ID 和目标目录行为。
- 原账号删除单文件及整个根目录，再恢复并逐文件核对路径、大小与可用哈希。
- 切换账号 B 后重建目录；确认 A 的 ID 不被误用于 B。
- 冷门磁链、分享过期、额度不足、429、账号失效时任务停留在可解释的状态。
- 浏览器直连和中转的实际视频编码、Range、HLS 清晰度与地址过期刷新。

实现结构与 HTTP 接口见 `docs/API.md`。验证记录见 `docs/VALIDATION.md`。

## 一次性按云端位置校正本地路径

仅在你手动整理 PikPak 后显式执行，普通扫描仍保留本地目标路径。停止服务并备份，再运行：

```bash
sudo systemctl stop pikpak-vault
sudo -u pikpak-vault /opt/pikpakvalue/vault backup --data /var/lib/pikpak-vault --archive /var/lib/pikpak-vault/before-path-reconcile.zip
sudo -u pikpak-vault /opt/pikpakvalue/vault reconcile-paths --data /var/lib/pikpak-vault --apply --report /var/lib/pikpak-vault/path-reconcile.json
sudo systemctl start pikpak-vault
```

省略 `--apply` 可预览。该命令完整扫描当前专用目录，并复核已绑定文件 ID；只更新本地目录和名称，保留来源相对路径、收藏、播放记录和本地 ID，必要时补建本地父目录。不会在云端创建、移动或改名。分页失败、路径冲突或扫描期间文件变化会阻止提交；专用目录之外、已删除、内容不符及本地主动回收站条目保留待处理。进行中的导入/恢复/整理任务会暂停，确认后再从任务页继续。
