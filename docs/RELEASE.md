恢复任务改为两路并行：PikPak 云端转存与 TelDrive 下载上传各执行一个任务，大文件传输不再占住云端恢复队列。磁链未命中云端缓存时，仍可能需要等待 PikPak 下载。

- 混合来源的恢复任务自动拆分，传输列表与详情显示所属通道，可分别暂停和重试。
- 旧恢复任务继续使用原 TelDrive 任务 ID、下载缓存、上传凭证及远端结果；云端来源保留完整批次与已提交记录，重启后先核对结果。
- 同一路同时只执行一个任务；PikPak 控制请求继续共用原有节流和限流退避，不增加上传分片并发。
- 共同父目录的创建与路径整理互斥；扫描不会用旧状态覆盖并行恢复的结果。移动后的资源仍恢复到最新位置。
- 阻止暂停后立即重试造成任务重入，服务退出等待两路任务保存进度。切号、账号异常、备份导入和缓存清理保护继续有效。
- 数据库结构保持 schema 4，无需迁移。已暂停或失败的旧任务不会因升级自动启动；手动重试后按来源分流。

验证包括上传期间云端恢复完成、同路并发上限、混合任务分流与事务回滚、来源批次和缓存保留、共同父目录去重、扫描竞争、退出续跑及任务标签的桌面/移动端交互。
